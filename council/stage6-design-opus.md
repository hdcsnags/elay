# Stage 6 §A — design-system contract (Opus lane, 2026-09-23)

*Grounded in the actual tree: `ui/theme/ElayTheme.kt` (20 lines, a stub), the 44 UI files under `ui/`, the three named shots, ADR-004, `androidApp/src/main/res/**`, `supabase/functions/rsvp/index.ts`, and the CMP 1.11.1 / material3 1.11.0-alpha07 pin in `gradle/libs.versions.toml`.*

## 0. What is actually there (the honest baseline)

`ElayTheme` passes **only** `colorScheme = if (isSystemInDarkTheme()) darkColorScheme() else lightColorScheme()`. No `typography`, no `shapes`, no parameter — which is why every shot is M3 baseline purple, and why no screenshot test or preview can force a scheme. Census of what the screens actually consume: 11 of 15 type roles (bodyMedium ×44, titleMedium ×22, bodySmall ×14, bodyLarge ×8, labelLarge/headlineSmall ×6, labelSmall ×5, titleSmall/titleLarge ×3, labelMedium ×2, headlineMedium ×1) — **`display*` and `headlineLarge` are unused**, so §B's editorial display face will not arrive by inheritance; it needs call-site edits. Spacing is 8/16/12/4dp (103 literals), with 48dp as the frozen touch floor and `HOUR_HEIGHT = 56.dp` as real layout math. `detekt.yml` has `MagicNumber: active: false` with the comment *"revisit when the token layer lands (ADR-004)"*.

Three colors already escape the theme: `PlanScreen.CAPACITY_OVERFLOW_COLOR = Color(0xFFFFB74D)`, and `CertaintyBadge.BUSY_CONTAINER_LIGHT/DARK` selected by a **direct `isSystemInDarkTheme()` call inside a component**. Three type sizes escape via `.copy(fontSize = 12/15/13.sp)` (PlanScreen:440, ProposalFeed:459/464). Every card is a bare `Card()` — M3's `surfaceContainerLow` + tonal elevation is exactly the gray slab in `stage5-e2e-01-today-wrapup.png`.

The launcher is the **AGP template**: `ic_launcher_background.xml` is `#3DDC84` plus 32 grid strokes; `mipmap-anydpi-v26/ic_launcher.xml` has background + foreground and **no `<monochrome>`**. The manifest hardcodes `android:theme="@android:style/Theme.Material.Light.NoActionBar"` — a *light* platform theme, so a dark-mode cold start flashes white before Compose paints and the edge-to-edge bars (`enableEdgeToEdge()` is already called) are platform-styled. There is no `values/themes.xml`, no `values-night/`, no `core-splashscreen`.

One good surprise: `shared/src/commonMain/composeResources/` exists, `libs.compose.components.resources` is already a commonMain dependency, and `Res.kt` is **already generated** at `elay.shared.generated.resources`. Bundled fonts need **zero Gradle change**.

## 1. The token layer (ADR-004, finally)

`shared/src/commonMain/kotlin/dev/elay/ui/theme/` — eight files, one owner:

- **`ElayColors.kt`** — `@Immutable data class ElayColorTokens(...)` with semantic names only: `surfacePaper`, `surfaceRaised`, `surfaceSunken`, `hairline`, `textEditorial`, `textPrimary`, `textMuted`, `accentPrimary`, `onAccentPrimary`, `accentQuiet`, `availabilityCalm`, `availabilityCaution`, `youTint`, `themTint`. Plus `elayLightColors()`, `elayDarkColors()`, `LocalElayColors`, and — the load-bearing piece — **`ElayColorTokens.toMaterialColorScheme(): ColorScheme`**. Because the ELAY tokens are the source and the Material scheme is a *projection* of them, all ~28 surviving `MaterialTheme.colorScheme.*` reads (surface, onSurface, onSurfaceVariant, surfaceVariant, surfaceContainerLow, primary, onPrimary, secondary, secondaryContainer, onSecondaryContainer, tertiary, outline, background) land on ELAY values for free the moment D1 merges.
- **`ElayType.kt`** — `elayTypography(f: ElayFontFamilies): Typography`, all 15 roles filled (size / lineHeight / weight / letterSpacing per §B), including the four currently-unused `display*`/`headlineLarge` slots reserved for the editorial voice.
- **`ElayShapes.kt`** — `ElayRadius` (`pill`, `card`, `sheet`, `field`, `chip`) + `elayShapes: Shapes` mapping extraSmall…extraLarge onto them.
- **`ElaySpacing.kt`** — `@Immutable data class ElaySpacing(hair=2, xs=4, sm=8, md=12, lg=16, xl=24, xxl=40, gutter=20, touchMin=48, hourHeight=56)` + `LocalElaySpacing`. `hourHeight` is a *layout* token, not decoration — Plan's timeline math depends on it.
- **`ElayElevation.kt`** — `dp` values **and** the dark-mode rule (below).
- **`ElayMotion.kt`** — `instant=0`, `quick=120`, `standard=220`, `expressive=400`, `deliberate=650` ms; `easeEditorial = CubicBezierEasing(0.2f,0f,0f,1f)`, `easeExit = CubicBezierEasing(0.4f,0f,1f,1f)`; `LocalElayMotion`.
- **`ElayFonts.kt`** — `@Composable fun elayFontFamilies(): ElayFontFamilies`.
- **`ElayTheme.kt`** — rewritten to `ElayTheme(darkTheme: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit)`, providing `LocalElayColors/Spacing/Motion` **outside** a `MaterialTheme(colorScheme = tokens.toMaterialColorScheme(), typography = elayTypography(...), shapes = elayShapes)`. The parameter is mandatory: without it neither `@Preview` nor a screenshot test can pin a scheme.

**Where Material still leaks — component-level overrides required** (read off the screens, not guessed): `Card()` defaults (~14 call sites across `ui/today`, `ui/plan`, `ui/together`) → `ElayCard` in a new `ElayComponents.kt`; `NavigationBar`/`NavigationBarItem` in `App.kt` (the purple pill indicator in all three shots) → explicit `NavigationBarItemDefaults.colors`; `ModalBottomSheet` ×2 (drag handle, scrim, container) — the share sheet in `stage3-e2e-02-share-sheet.png`; `AlertDialog` ×2 (`BlockDetailDialog`, `LeaveConfirmDialog`); `FilterChip` ×3 sites and `AssistChip` (the wrap-up row's border/container); `OutlinedTextField` ×5 (label, indicator); `Button`/`OutlinedButton`/`TextButton` contentPadding + shape; `CircularProgressIndicator`. Material3 is on its own alpha train (`1.11.0-alpha07`, versioned independently per ADR-004) — every override goes through public `*Defaults` APIs.

## 2. Light + dark from one palette; contrast floors

One palette = six ramps (`ink`, `paper`, `accent`, `accentDeep`, `caution`, `calm`), each a 12-step tonal ramp. Derivation rules, not inversion:

1. **Surfaces**: light picks paper t98 / t96 / t93 (paper → raised → sunken); dark picks ink t06 / t12 / t17. Dark's *raised* is **lighter** than its base — elevation in dark is a surface step, never a shadow (Compose shadows are near-invisible on dark ground).
2. **Text**: light t10 / t30 / t50 (editorial → primary → muted); dark t95 / t85 / t65.
3. **Accent**: light takes accent t40 with `onAccent` = paper t99; dark takes accent t80 with `onAccent` = accentDeep t20, and **drops chroma ~15%** to kill halation on OLED.
4. **Hairline**: light t88, dark t28 — and a hairline is never the *sole* boundary between two interactive regions.
5. **Shadow alpha halves** in dark; `tonalElevation` is pinned to `0.dp` everywhere so M3's own tint never re-enters.

**Floors (WCAG 2.2 AA, both schemes):** body/label/title text ≥ **4.5:1** (1.4.3); text ≥24px regular or ≥18.66px semibold ≥ **3:1**; non-text UI boundaries — chip outlines, field indicators, the four capacity-gauge segments, the certainty pill, focus rings — ≥ **3:1** against adjacent (1.4.11); `onAccentPrimary` on `accentPrimary` ≥ **4.5:1**; focus ring ≥ **3:1** against both its own fill and the surface behind. Enforcement is a pure-Kotlin `commonTest` (`ElayContrastTest`) that computes WCAG relative luminance over an explicit pair table for `elayLightColors()` and `elayDarkColors()` — a rail, not an eyeball. §B 5.4's colour-independence rule stands unchanged: every state still carries its own text.

## 3. Icon + splash pipeline — exact deliverables

Vectors (D3): `drawable/ic_launcher_foreground.xml` (108×108 viewport; mark inside the **66dp safe circle**, i.e. ±33 from centre; no stroke thinner than 2 viewport units; flat fills, no gradients); `drawable/ic_launcher_background.xml` (one flat `<path>` replacing the `#3DDC84` grid wholesale); `drawable/ic_launcher_monochrome.xml` (**same geometry, single `#FFFFFFFF` fill, no background** — the system tints it; a two-tone monochrome layer is a bug). `mipmap-anydpi-v26/ic_launcher.xml` **and** `ic_launcher_round.xml` gain `<monochrome android:drawable="@drawable/ic_launcher_monochrome"/>` (API 33+, inert below). Legacy `mipmap-{m,h,xh,xxh,xxx}dpi/ic_launcher.png` at 48/72/96/144/192px for API 24–25 (minSdk is 24); the `_round` PNGs regenerate to match.

Splash (LEAD, per stage-5 amendment 4): add `androidx.core:core-splashscreen` to the catalog + `androidApp/build.gradle.kts`; create `values/themes.xml` + `values-night/themes.xml` with `Theme.Elay.Starting` (parent `Theme.SplashScreen`) carrying `windowSplashScreenBackground`, `windowSplashScreenAnimatedIcon` (288×288dp drawable, mark inside the inner 192dp — the OS masks to a circle), and `postSplashScreenTheme = Theme.Elay` whose `android:windowBackground` is ELAY paper/ink per mode. Manifest swaps `@android:style/Theme.Material.Light.NoActionBar` → `@style/Theme.Elay.Starting`. `MainActivity` calls `installSplashScreen()` **before** `super.onCreate`, and **must not** wire `setKeepOnScreenCondition` to `SessionState.Refreshing` — `App()` already renders its own `LoadingScreen()`; holding the system splash across a slow token refresh is the classic cold-start regression.

iOS: `iosApp/iosApp/Assets.xcassets/AppIcon.appiconset/app-icon-1024.png` regenerated at 1024×1024 sRGB, **no alpha, no pre-rounded corners**, plus `AccentColor.colorset` set to `accentPrimary` for both appearances. iOS has no adaptive or monochrome layer — that one PNG is the whole contract.

## 4. Typography implementation: **bundled**

Downloadable Google Fonts is **forbidden**: `androidx.compose.ui.text.googlefonts` is an androidMain-only artifact requiring the Play-services font provider and a certificate list — unavailable on iOS, absent on non-GMS devices, and it introduces a first-frame FOUT that makes screenshot verification non-deterministic. Bundled wins on all three counts and costs nothing in build work.

Mechanism: drop static `.ttf` into `shared/src/commonMain/composeResources/font/`, reference the already-generated `elay.shared.generated.resources.Res.font.*`, compose `FontFamily(Font(Res.font.x, FontWeight.Medium))` inside `@Composable elayFontFamilies()`. **Budget: 600 KB hard ceiling across all faces**, practically four Latin-subset static faces (display regular, display medium, body regular, body medium) at 90–160 KB each. No italics, no weight §B does not actually call, no variable build that exceeds the ceiling. Fallback rule: a `FontFamily` list's later entries are Compose's fallback chain, so every ELAY family declares the platform default last; the **web RSVP page deliberately keeps its existing system stack** and matches ELAY by scale, colour and rhythm rather than by face — shipping font files from an edge function is not worth the bytes.

D4/D5/D6/D7 are mutually disjoint and parallel. **Web parity mechanism:** `contracts/fixtures/design-tokens.json` is the single machine-readable source; the Kotlin side is pinned by a `commonTest` asserting every `ElayColorTokens` hex matches it, the Deno side by a test asserting the ten `:root` custom properties (`--bg --surface --on --on-var --primary --primary-on --outline --accent-bg --danger-bg --pill-bg`) match the same file. The page already has the `:root` + `@media (prefers-color-scheme:dark)` structure — only the values change.

**Riskiest visual regressions, named:** (1) Plan's `DayTimeline` positions cards by `offset(y = TIMELINE_HEIGHT * fraction)` with `HOUR_HEIGHT = 56.dp` — a 15-minute block is 14dp tall, so any radius/padding token above ~6dp turns it into a blob or clips its label; require a screenshot with a 15-minute block. (2) `WrapUpCard`'s five-chip `FlowRow` with two-line labels at `heightIn(min = 48.dp)` — a letter-spacing change re-wraps it; the 48dp floor and the five-chip set must both survive. (3) The dark-mode white cold-start flash (manifest theme) plus the three hardcoded colours failing contrast on a new dark surface. (4) `CertaintyBadge` reading `isSystemInDarkTheme()` directly will desync the moment `ElayTheme` gains its `darkTheme` override.

## 6. Out of scope, and three failure modes

**Out:** gamification of any kind (streaks, badges, confetti, celebratory progress); an illustration system — §B may specify **at most one** shared minimal vector for empty states, never per-screen art; any copy rebrand (spec §2's calm-ops tone and every frozen stage string stand); Material3 Expressive (still alpha — ADR-004's revisit trigger is unmet); Nav3; any change to the four-tab structure or route contracts; **dynamic color / Material You wallpaper extraction** (it hands the brand to the wallpaper); an in-app theme-toggle *surface* (`ElayTheme` gains the parameter; the Settings row is deferred); flipping `detekt MagicNumber` back on before D6 merges.

1. **Replacing `MaterialTheme` or forking a Material3 component source is forbidden BECAUSE** ADR-004 pins Material3 as the primitives layer and the artifact is on an independent alpha train whose internals move between builds; **theming through `MaterialTheme(colorScheme, typography, shapes)` plus thin ELAY wrappers over public `*Defaults` APIs remains required**, and any component unreachable that way is recorded as a named override in `ui/theme/ElayComponents.kt`, never copy-pasted.
2. **A second colour source is forbidden — no `Color(0xFF…)` literal and no `isSystemInDarkTheme()` call outside `ui/theme/` — BECAUSE** the three existing leaks already produce a look the theme cannot move and the contrast test cannot see; **a `LocalElayColors` semantic read remains required for every non-Material hue**, and those three literals must be migrated inside their owning slice, not merely re-homed.
3. **Deleting frozen copy, `semantics{contentDescription}`, the 48dp touch floor, or §B 5.4's colour-independence in the name of beauty is forbidden BECAUSE** stages 2/4/5 froze them as binding contract text and a11y regressions are invisible in a screenshot review; **every redesigned surface remains required to keep its verbatim strings, its semantics, its 48dp minimum bounding box, and a text label on every state that also carries colour** — this stage moves type, colour, space and motion, never words or semantics.
